# Post-Launch

**Weekly (15 min)** → append to `docs/product/METRICS.md`:
1. Pull the success metric + inputs (activation, retention D1/D7/D30, conversion, crash-free %, performance) from analytics/Sentry/stores (MCP if connected, else ask owner for numbers).
2. Compare to last week and target; flag changes > 20%; one-line hypothesis each.
3. Synthesize new feedback (store reviews, support, interviews): themes, counts, quotes.
4. Monthly: ask the owner for the month's bills (AI tools, hosting, stores) → `docs/product/COSTS.md`; compare cost vs the success metric (cost per active user / per paying user).
5. Output: 3 findings · 1–3 actions → PLAN.md tasks.

**Every 2–4 weeks: retro** → `docs/product/LESSONS.md`: what worked · what didn't · what we'll change · kit improvements (skill/rule/standard that was wrong or missing).

**Outcome log (weeks 4, 12 and when parked)**: add/update this project's row in the kit's `portfolio/OUTCOMES.md` (verdict & score at approval vs what happened, metric vs target, total cost from COSTS.md) and, when a pattern repeats across projects, a calibration note for evaluate-idea.

**Project end / major milestone**: list kit improvements as concrete edits (file + change) for the Product Kit repo's `LESSONS.md` and CHANGELOG.

Decide with evidence: persevere, iterate, or pivot — tie back to EVALUATION kill criteria.
