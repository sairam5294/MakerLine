# Examples — real projects built with the kit

Each folder is one project taken through the kit, with the documents the skills produced and an honest note on what the kit got wrong. They are the fastest way to see what "good" looks like before you start your own idea, and they double as evals: when a skill changes, re-running it on these briefs should not get worse.

| Project | Path | Kit path exercised | Status |
| --- | --- | --- | --- |
| RhythmBuddy — macOS wellness-reminder menu-bar app (Python / PyObjC) | `rhythmbuddy/` | Existing codebase adopted with `upgrade-project`, then quality-review, test-plan and ship-checklist | In progress (Oct 2026) |
| ClubSlot — society amenity booking (idea stage, blind eval) | `idea-pack-clubslot/` | Full Idea Pack: evaluate-idea (Pivot), COMPETITORS, design-direction + wireframes, draft PRD, one-pager | Idea stage (Oct 2026) |

## What each example contains

```
examples/<project>/
  README.md            one page: what it is, which kit phases ran, what the kit got wrong, links
  docs/product/        the kit's own outputs for this project (brief, evaluation, PRD, reviews…), with private data removed
```

## Adding yours

Copy the layout above, strip anything private (names, keys, real metrics you don't want public), and open a pull request using the "New skill, agent, or tool adapter" template. See [CONTRIBUTING.md](../CONTRIBUTING.md).
